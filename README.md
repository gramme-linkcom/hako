# Hako — 自宅用ミュージックサーバー

自分の音楽フォルダをスマホ（Android）やPCのブラウザから聴ける、セルフホスト型の音楽サーバーです。
Go製のサーバー1つ ＋ インストール可能なWebアプリ（PWA）です。

## 機能

- フォルダをスキャンしてタグから **アーティスト → アルバム → 曲** に整理（CD1/CD2フォルダの統合、コンピレーションは Various Artists に自動判定）
- 古いMP3の **Shift_JISタグの文字化けを自動修正**
- カバー画像：フォルダ内の `cover.jpg` / `folder.jpg` など、なければ埋め込み画像
- 再生：ブラウザが対応する形式（MP3 / AAC / FLAC / Opus / Vorbis / WAV）はそのまま配信（シーク対応）。
  WMA・APE・ALAC など非対応形式や「音質を下げる」設定時は、ffmpegでMP3に変換しながら少しずつ送信
- 画面下のミニプレイヤー、全画面の再生画面、再生キュー、シャッフル/リピート
- プレイリスト、お気に入り、再生回数（よく聴く曲・最近聴いたアルバム）
- 歌詞表示：曲と同じ名前の `.lrc`（時間同期）や埋め込み歌詞
- **ハイレゾ / ロスレスのバッジ**と絞り込み（ハイレゾ = ロスレスかつ 24bit 以上 または 48kHz 超、DSD 含む）
- **音量の均一化**：ReplayGain / R128 タグを使い、タグがない曲はスキャン後に ffmpeg（EBU R128）で自動解析。
  設定で「自動 / 曲ごと / アルバム単位 / オフ」と基準音量（-12〜-18 LUFS）を選べます。
  ブラウザの仕様上、音量は下げる方向にしか調整できないため、基準より静かな曲はそのままの音量で再生されます
- ロック画面・通知からの操作（Media Session）
- 複数ユーザー（再生回数・お気に入り・プレイリストはユーザーごと）
- 対応形式: mp3, flac, m4a, aac, ogg, opus, wav, wma, ape, aiff, wv, mpc, dsf など（ffmpegが読めるもの）

## 起動

1. `docker-compose.yml` の音楽フォルダのパスを書き換えます（左側がホストのパス）。

   ```yaml
   volumes:
     - ./data:/data
     - /path/to/your/music:/music:ro
   ```

2. 起動します。

   ```bash
   docker compose up -d --build
   ```

3. ブラウザで `http://<サーバーのIP>:8096` を開き、最初に管理者アカウントを作成します。
4. 「設定」→「音楽フォルダ」で `/music` を追加すると、スキャンが始まります。

以降は60分ごとに自動で再スキャンします（`HAKO_SCAN_INTERVAL_MIN` で変更、`0` で無効）。
設定画面の「スキャン」ボタンからすぐに反映することもできます。

## スマホにアプリとしてインストールする（Android）

Chromeで開いてメニューの「アプリをインストール」を選びます。
**PWAのインストールにはHTTPSが必要です**（`http://192.168.x.x` ではインストールできません）。次のどちらかがおすすめです。

- **Tailscale**：サーバーで `tailscale serve --bg 8096` を実行すると、`https://<マシン名>.<tailnet>.ts.net` で外出先からも安全に使えます
- **リバースプロキシ（Caddy など）**：独自ドメインで公開する場合

  ```
  music.example.com {
      reverse_proxy hako:8096
  }
  ```

## 環境変数

| 変数 | 既定値 | 説明 |
| --- | --- | --- |
| `HAKO_DATA` | `/data` | データベースとキャッシュの保存先 |
| `HAKO_ADDR` | `:8096` | 待ち受けアドレス |
| `HAKO_SCAN_INTERVAL_MIN` | `60` | 自動スキャンの間隔（分）。`0` で無効 |
| `HAKO_FFMPEG` / `HAKO_FFPROBE` | `ffmpeg` / `ffprobe` | ffmpegのパス |
| `HAKO_TRUST_PROXY` | （なし） | リバースプロキシ（Caddy / Tailscale serve など）の後ろで動かすときに `1` にすると、`X-Forwarded-For` から接続元IPを判定します。プロキシを使わない場合は設定しないでください（偽装されるため） |

## セキュリティ

- **2段階認証（TOTP）**：設定 → セキュリティ から有効化。Google Authenticator などで QR コードを読み取ります。
  紛失時用の回復コード（10個・各1回限り）を発行します。管理者は他のユーザーの2段階認証を解除できます
- **総当たり対策**：同じアカウントで15分間に5回失敗すると15分ロック、同じIPから20回失敗すると30分ロック（2段階認証のコード入力も対象）
- **パスワード**：PBKDF2-HMAC-SHA256（60万回）で保存。8文字以上。存在しないユーザー名でも応答時間を揃えて推測を防止
- **セッション**：トークンはハッシュ化して保存、90日で失効（使っていれば延長）。ログイン中の端末を一覧・個別ログアウト可能。
  パスワード変更・2段階認証の有効化時は他の端末を自動でログアウト
- **その他**：CSRF対策（別サイトからの書き込み操作を拒否）、CSP などのセキュリティヘッダー、HTTPS 時は Secure Cookie と HSTS
- ログイン失敗やロック、2段階認証の変更はサーバーログ（`docker compose logs hako`）に記録されます

## データについて

- `./data/hako.db` にユーザー・再生回数・お気に入り・プレイリストが保存されます。バックアップはこのフォルダごとコピーしてください。
- 音楽フォルダは読み取り専用でマウントしており、Hakoが音楽ファイルを書き換えることはありません。
- フォルダが一時的に見えなくなった（NASのマウント切れなど）場合、ライブラリが消えないように削除処理をスキップします。
